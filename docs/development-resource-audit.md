## 4. “做开发”与“学开发”的边界

### A. 明确服务实际开发的工具、平台或查询资料

- **实际工具 / 环境**：Replit、CodeSandbox、StackBlitz、Vite。
- **代码与协作平台**：GitHub、GitLab、Bitbucket。
- **云服务 / 后端平台**：阿里云、腾讯云、华为云、火山引擎、Cloudflare、Supabase。
- **工作中直接查阅的文档与参考**：MDN Web Docs、Can I use、VS Code Docs、Git Documentation、GitHub Pages、Vercel Docs。
- **问题排查社区**：Stack Overflow，描述明确强调排查具体错误和实现问题。

以上20项的本地描述能直接支持实际开发使用；不代表它们没有学习用途。React Docs单列为下述边界项。

### B. 明确的教程 / 课程 / 学习资料

当前21项中没有明确标为课程平台或教程站的实体。**React Docs**的描述明确写“学习组件、状态和交互界面构建”，有学习资料性质，但名称和描述同时明确它是官方文档，不能因此将整项认定为只适合学习。

对照开发学习中的四项：JavaScript.info、freeCodeCamp、roadmap.sh分别强调系统学习、课程、学习路线；W3Schools兼有查语法和入门练习用途。这些是当前学习区已有资源，不属于本次21项。

### C. 工作查询与学习双用途

- **React Docs**：官方文档与学习组件/状态并存，是最明确的双用途项。工作查询用途由官方文档性质推断，不声称已检查具体页面内容。
- **MDN Web Docs**：技术文档可用于工作查阅，也可用于理解Web技术；后者是基于文档性质的合理使用场景，当前描述没有明确系统课程。
- **VS Code Docs、Git Documentation**：可查快捷键、扩展说明、命令和工作流，也可能用于熟悉工具；不能把文档本身等同于软件安装或系统课程。
- **GitHub Pages、Vercel Docs**：部署、预览、域名配置等操作性资料，既能按需查询也能学习部署流程，主要描述仍贴近实际发布。
- **Stack Overflow**：能通过问答理解技术，但当前描述指向解决具体问题，不是系统课程。
- **Can I use**：可帮助理解兼容差异，但首要功能明确是查询，不宜仅因“获得知识”而归入学习区。

### D. 疑似更适合开发学习的项目

**优先人工复核React Docs**：现有描述更突出学习，值得后续判断其主要使用方式。但按“实际项目会直接使用或查询”的原则，官方文档留在开发区也有充分理由；当前信息不足以判定必须移走。

其他技术文档具有学习价值，但没有明确证据说明它们更适合仅放学习区。本轮不建议仅凭“文档”或“学习”字样机械移动，不新增共享。开发学习中的W3Schools也具有工作查询用途，说明两区是主要使用目的的区分，不是互斥能力分类。

## 6. 当前section混杂问题

- **文档与平台（11项）过宽**：混合Web文档、云计算/部署、浏览器兼容参考、问答社区和代码托管。标题能笼统容纳这些内容，但不能清楚区分“查资料”和“使用服务”。其中社区、兼容查询的性质也没有在名称中体现。
- **开发工具（5项）混合本体与文档**：VS Code Docs、Git Documentation是文档；Replit、CodeSandbox、StackBlitz才是在线编辑/开发环境。将前两项直接理解为IDE或Git软件本体会产生误读。
- **项目构建（5项）范围与标题不完全一致**：Vite是构建工具；React Docs是官方文档；GitHub Pages、Vercel Docs是托管/部署文档；Supabase是后端/数据库平台。“项目构建”覆盖了开发、文档、发布及后端服务，而不只构建步骤。
- **前端、后端、云服务与Git相关入口分散**：前端文档横跨文档与平台、项目构建；代码托管与Git文档分处两组；云平台与部署文档也分处两组。这是现状观察，不在本轮决定应如何重组。
- **API与包资源**：MDN描述包含Web API，Supabase包含实时接口，但没有明确独立的API目录或包/依赖仓库实体；不强行补出这些类别。
- **教程与社区**：未发现明确课程平台混入；React Docs有学习边界，Stack Overflow是问题排查社区，应与软件/云服务性质区分。

当前三个section分别11、5、5项，没有只有1项或2项的section，也没有根据数量可认定“过细、无独立必要”的分组。主要问题是分类过宽及工具、服务、文档混合。本轮不提出最终重构方案。
