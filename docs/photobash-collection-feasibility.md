## 7. 图片使用条件

来源：[官方 Knowledge Base](https://www.photobash.org/knowledge-base)，页面标示条款更新日期为 2024-11-07。

**明确限制：** Terms & Conditions 第 2 节 (c) 明确禁止 data mining、spidering、crawling、scraping 等行为。这直接触发本轮停止条件。授权协议还限制原始内容再分发及过度下载、镜像；不能把购买素材许可自动视为建立预览图库的授权。

**未找到针对本用途的许可：** 所检查条款未提供“第三方保存目录封面并在个人公开网站展示”的明确许可。知识产权条款将站点展示材料归于官方，公开 CDN 可访问性不等于转载授权。

**署名边界：** 条款对符合许可的创作使用说明可免署名，但没有证明这同样适用于重新展示官方封面；添加来源链接不能代替许可。

**适用结论：** 本轮既未证明封面留存获得许可，也未证明个人公开目录展示获得许可。应向官方核实自动获取、缩略图保存/展示、署名和更新范围；本报告不作更广泛法律判断。

## 8. 采集方式比较与正式方案建议

以下是获得官方明确授权后的评估顺序，不是本轮已验证可用的实现方案，也不应用于绕过现有限制。

| 方式 | 当前证据与后续判断条件 |
| --- | --- |
| Python 标准库 HTTP | 本机两次请求均 DNS 失败；网络恢复并获得许可后，优先评估是否可直接获取官方允许的目录来源，依赖最少 |
| requests | 不能解决条款限制；当前无证据表明比标准库必要，不安装 |
| HTML 解析 | 需先证明原始 HTML 含完整目录卡片及其标题/项目/拼图封面绑定；目前未证实 |
| 官方结构化数据或接口 | 未发现并实测获准用于此用途的接口；可向官方申请 feed、CSV/JSON 或授权元数据，不猜测隐藏端点 |
| 浏览器自动化 | 仅在官方允许且普通 HTTP 确实缺少所需数据时评估；本轮没有“必须浏览器”的证据，不安装 Playwright |

**当前最实际的路线是先取得官方允许的数据与图片使用方式。** 如果官方能提供产品清单和缩略图授权，直接消费该来源比对页面结构持续采集更稳妥。若只有链接许可，可以先评估仅含文字与官方跳转的目录；封面改用明确获准的媒体。若没有采集授权，使用用户自行整理或官方直接提供的授权数据，不将“手动操作”当作自动绕开限制的替代方式。

## 9. 去重设计与全量风险

本轮没有重复样本可供验证。以下仅为未来设计建议：

1. 获得数据后优先使用实际存在的官方稳定产品 ID；本轮没有确认该字段。
2. 如果只有项目 URL，以核验过的规范化 URL 建立稳定本地 ID 映射，不随标题改名重新生成 ID。
3. 同一包出现在多个分类时合并 `categories`；同名不同包不合并，同图不同包也不自动合并。
4. 英文标题、图片 URL 不作为唯一键；尺寸参数和 CDN 路径可能变化。
5. 保留人工译名覆盖层；只有完整、成功的获准同步结果才用于判断删除。

全量风险包括当前明确采集限制和封面使用权不明；以及尚未验证的分页覆盖、重复分类、产品 ID 稳定性、CDN 参数、过期图片地址、网络可达性、改版和图片总体体积。本轮不能提供全量预计数量、成功率或耗时。
