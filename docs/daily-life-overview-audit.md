## 3. 四个 view 的结构评价

### 游戏：建议深入整理

- 30 项分成 7 组，数量并不失控，但 section 同时使用了“内容形态”（互动小游戏）、“任务”（下载、购买）、“内容关系”（官方网站）和“兜底分类”（其他资源）多套逻辑。
- “游戏社区/攻略”把媒体、攻略、下载/补丁和社区混在一起；“官方网站”实际主要是发行商、商店与游戏平台，并不都是单纯官网。
- “其他资源”包含数据库、时长查询、评分聚合和运行故障排除，五项用途差异明显。
- 当前结构仍可用，但已经有足够证据支持下一轮单独做完整资源审计；本轮不提出最终重组方案。

### 影视：轻微整理即可

- 17 项中的 15 项已按观看、搜索、下载三个主要场景清楚分开。
- 两个 singleton section（播放工具、影视查询）不是错误，但显示当前覆盖不均；“影视查询”只有 IMDb，兼具数据库、评分与社区属性。
- 当前没有独立字幕、资讯或影评资源；这表示现有集合主要面向观看和资源发现，而不是分类遗漏的直接证据。
- 不需要为结构统一而做大规模重构，适合先做一次轻量专项核对。

### 音乐：保持现状

- 2 项都直接服务于日常听音乐、歌单或发现，单一“收听与发现”section 足够清楚。
- 网易云音乐偏客户端下载，Spotify 偏 Web 流媒体，但两者在当前 view 的使用目的相同。
- 资源少不构成撤销独立 view 的理由。该 view 可作为稳定入口继续扩展，目前没有必要细分。

### 日常工具：建议深入整理

- 30 项看似是“工具”，实际主要由综合导航、电子书、网盘搜索/存储、邮箱和地图五类服务构成；与文件/格式处理、图片处理、翻译、计算等通用“在线小工具”并不相同。
- “其他工具”三项全部是地图，同时另有一个“地图”singleton section；同一种使用场景被两套 section 分开。
- “网盘资源”同时放置搜索引擎和云存储服务；“互联网资源索引”是 8 个跨主题聚合入口，天然较宽。
- 存在同名不同 ID 的两个谷歌地图实体，且分别位于“其他工具”和“地图”。这使该 view 最值得优先做完整专项审计。

- 平台/商店/发行商入口：Steam、Epic Games Store、GOG、Ubisoft、Origin/EA App、Xbox；“官方网站”这个标题不能完整表达其商店与平台性质。

- MOD/补丁：3DM MOD站、游侠补丁、Nexus Mods、Mod DB、Steam创意工坊；其中既有下载站也有社区/平台。
- 数据库、评分、查询与工具：Steam Database、HowLongToBeat、OpenCritic、Metacritic、PCGamingWiki 全部落在宽泛的“其他资源”。

与相邻领域的实际边界：

- 与「创作与工作 → 游戏制作」同 ID 共享：0。
- 与「学习与研究 → 游戏设计」同 ID 共享：0。
- 当前 30 项都以玩游戏、购买、获取、社区、攻略、MOD 或玩家侧查询为主，没有 catalog ID 层面的“游戏制作”混入。
- PCGamingWiki 同时位于「设备与环境 → 系统与设备 → 游戏运行与优化」，说明它兼有玩家资料与环境排障两种明确用途；这是共享，不是重复。

结论：边界总体仍是“玩游戏”，主要问题来自内部 section 的分类维度混用，而不是与游戏制作/游戏设计混淆。

## 5. 影视专项观察

当前组数与数量为：播放工具 1、影视在线 9、聚合搜索 3、影视下载 3、影视查询 1。

- 观看入口是主体：9 项，占 17 项的一半以上。
- 资源发现有两种方式：3 个聚合搜索入口，以及 IMDb 这个数据库/社区入口。
- 下载入口 3 项，边界清楚。
- IINA 是本地播放工具，与 16 个网站型影视资源性质不同，因此形成 singleton section；它同时与设备软件 view 共享同一 ID。
- 当前没有明确的字幕专站、影视资讯专站或独立影评站；IMDb 的 description 同时涵盖数据库与社区，评分含义由其产品性质隐含但没有写进 description。
- 网飞猫与网飞猫备用是同一平台的主/备用入口，被建成两个实体；应作为历史数据关系记录，而非在本轮合并。
- 「学习与研究 → 美术」中的电影拉片/影视参考资源与本 view 没有同 ID 共享；主题都与电影有关不构成实体共享。

结论：现有结构基本按消费流程组织，只有 singleton、IMDb 的复合性质和主/备用入口值得后续轻量核对。

## 12. 与整体四大区架构的边界

按“创作与工作 = 做事情时直接使用；学习与研究 = 学习、知识、研究；日常与生活 = 娱乐、消费、日常实用；设备与环境 = 软件安装、系统、设备、插件、个人环境”观察：

- 游戏整体符合娱乐/消费边界。Steam、Epic Games Store 同时是游戏平台软件，已通过同 ID 与设备软件共享；PCGamingWiki 的排障用途也已与系统与设备共享。没有与游戏制作或游戏设计的同 ID 冲突。
- 影视整体符合观看、搜索、下载和查询的消费边界。IINA 属于安装型软件，但当前已与设备软件共享，因此不是只能二选一的边界错误。
- 音乐两项都符合日常收听。网易云音乐在设备软件中共享，清楚区分“安装环境”与“日常使用”；没有和音乐学习或音视频创作发生 ID 混用。
- 日常工具中的百度网盘既是日常云存储也是软件，已共享至设备环境。其余网盘与邮箱当前以 Web 服务使用为主，没有明确要求进入设备环境。
- 电子书资源具有潜在学习价值，但现有 descriptions 指向阅读、搜索与下载，并无学科/课程性质；不能仅凭“书”判定应移到学习区。
- 综合资源导航可能覆盖多个大区，但当前实体描述不足以证明具体边界冲突。它们的主要问题是粒度宽，而不是可客观确认的错区。
- 两个谷歌地图实体的问题是同 view 内的重复与 section 分裂，不是四大区边界冲突。
- 未发现明确应属于创作与工作、却只存在于日常与生活的实体。
